T031　LLM が作った変数を回帰に使うときの測定誤差の補正

1. 結論を先に

条件つきで勧める。元の構想（偏りの大きさを示し、補正を実装する）のままなら勧めない。

  • 元の構想は、既に済んでいる。補正の理論・公開パッケージ・実務指針・経済学での適用例が、2025〜2026年に出そろった。
  • 一次採点の「公開パッケージは確認できなかった」は誤りだった。R と Python に少なくとも7つある（7章）。
  • 残る隙間は「手法どうしの横並びの比較」と「どれを使うかの判断手順」である。新しい推定量ではなく、ベンチマーク論文と統一ライブラリなら勝ち目がある（筆者の見解）。

いちばんの勝ち筋: 5系統の補正を、経済学で典型的な設定（説明変数側の誤り、固定効果、クラスタ、検証標本の有無）で同じ土俵に載せ、どの条件でどれが壊れるかを示す比較と、それを1つの入口で呼べるライブラリ。

いちばんの懸念: 有力な著者のチームが、少なくとも10組、同じ場所に密集している（7章）。比較論文も、彼らの次の1本で埋まるおそれがある。

2. 問いと、なぜ今か

問い

LLM や機械学習が付けたラベル・点数を回帰に入れると、推定値はどれだけ偏るか。どの補正を、どの条件で使えばよいか。

答えが出ると誰の判断が変わるか

誰変わる判断
テキスト・画像から変数を作る実証研究者人手ラベルを何件取るか。どの補正を使うか。補正なしで報告してよいか
査読者・編集者LLM 変数を使う論文に、何の点検を求めるか
このラボ自身段階5（文献をデータにする）で AI が抽出した値を、どう補正して使うか

なぜ今か

  • 既存研究の再現で、LLM のラベルを使うと誤った結論が頻発すると報告された。37課題・21研究の再現である（Baumann ほか (2025)。要約のみ確認。割合の数値は本文未確認のため書かない）。
  • モデルやプロンプトを変えると、係数の符号・大きさ・有意性が変わると報告された（Ludwig・Mullainathan・Rambachan (2025)）。
  • 補正手法は2023年以降に急増した。系統が5つに分かれ、利用者から見て選べない状態にある（筆者の見解。3章の表が根拠）。

関連テーマとの切り分け

テーマ扱うものT031 との境界
T031（本書）低次元のラベル・点数（2値・多値・連続）を回帰の変数に使うときの、偏りの補正と推論「真の値」が定義でき、人手で測れることが前提
T033LLM を使ってよい条件の検査（学習データの漏れ、プロンプトへの感度、検証標本の要否）補正の前の関門。漏れの検査は T033 に置く。T031 は「検証標本がある／無いときに、どう補正するか」だけを扱う
T039高次元の埋め込みを、調整変数として回帰に入れるときの推論埋め込みには「真の値」が無い。測定誤差ではなく、高次元の調整の問題。T031 では扱わない
  • 重なりが大きいのは T033 である。Ludwig らの枠組みは、漏れの検査と補正の両方を1本で扱っている。
  • T031 と T033 を両方着手するなら、1つのプロジェクトにまとめる方がよい（筆者の見解）。
  • Battaglia らの論文は、トピックの割合のような「真の値が定義しにくい」変数も扱う。この部分は T039 に近い。

Battaglia・Christensen・Hansen・Sacher (2024)。v5 は2025年4月生成変数を説明変数に入れると、偏りが一次のオーダーで残る。問題は標準誤差より偏りである。偏り補正つきの信頼区間と、同時推定を提案。2値ラベル・トピックの割合・指数を扱う偏りの式は特定の設定だけ。同時推定は計算が重い。分類器を検証データで調整すると推論が複雑になる。誤差が標本誤差より大きい場合は分析から外している。どの手法・モデルが影響を受けやすいかは今後の課題、と著者が書いている本文（v4 の HTML の前半約3分の1。導入・理論の設定・関連研究）
Christensen・Hansen (2026)。AEA Papers and Proceedings 116巻実証家むけの指針。検証データが無くても使える補正を説明。賃金とリモートワーク、FOMC 声明の感情と長期金利の2例。Python パッケージ ValidMLInference を提供自分たちの系統（A）の指針である。他系統との比較は要旨には無い要旨（書誌ページ）

Angelopoulos・Bates・Fannjiang・Jordan・Zrnic (2023)。Science予測を使った推論（PPI）。平均・分位点・回帰係数の信頼区間。予測モデルに仮定を置かない予測されるのは主に結果変数。説明変数側は後続研究に持ち越し要旨

Carlson・Dell (2025)。v3 は2026年2月欠測データの問題として統一（MAR-S）。平均・回帰・操作変数・差の差・回帰不連続まで。予測を集計・変換してから使う場合も扱う。R の実装つき人手の注釈が真の値を明かすことが前提。注釈の抽出は観測変数を条件に無作為であること。クラスタは拡張として触れるだけ本文（v3 の HTML の前半約3分の1。実例の節は未読）

Burtch・McFowland・Yang・Adomavicius (2026)。Management Science に掲載予定アンサンブルの個々の学習器から操作変数を作る（EnsembleIV）。検証標本が要らないLLM のように内部の学習器を取り出せないモデルでは、そのまま使えない（筆者の見解。本文未確認）要旨

割れている点

  • 検証標本は必須か。 Ludwig らは必須と言う。Christensen・Hansen は、経済学では検証データが無いことが多いとして、不要な補正を勧める。操作変数の系統も不要とする。
  • 操作変数型は妥当か。 Battaglia らは、操作変数型の補正は検証標本と本標本が同程度の大きさのときだけ妥当で、信頼区間の被覆が不足すると書いている（v4 本文）。Burtch らと Canen・Enamorado は妥当と主張する。同じ設定での直接の比較は、検索では見つからなかった。
  • DSL と PPI のどちらが良いか。 EMNLP の比較では、データによって逆転する。

  • 全部の組合せは多すぎる。中心の設定を1つ決め、軸を1つずつ動かす。
  • 半合成の実験も入れる。人手ラベルのある公開データで、実際の LLM の誤りをそのまま使う。真の係数は、全件の人手ラベルで推定した値とする（EMNLP の比較と同じやり方）。
  • 1周は数分〜数時間で回ると見込む（筆者の見解）。同時推定（系統 A の one_step）だけは重い。

この設計の弱点

  • 既存パッケージは、対応する設定が違う。「比べられない組合せ」が多く出る。それ自体を表にして示す。
  • 他人の手法を自分で実装すると、実装の誤りで不当に悪く見せるおそれがある。著者の公開コードを使い、論文の数値を再現してから比べる。
  • 設定を選ぶ自由度が大きい。設定と評価指標をロックで固定する（手法トラックの決まり）。

## 1. 結論を先に

**条件つきで勧める。元の構想の半分（選択記録に離散選択の需要モデルを当て、人と比べる）は済んでいるので、そのままなら勧めない。**

- 離散選択モデルは既に当てられている。Allouah ほかは条件つきロジットで位置・価格・バッジの係数を出し、Kireyev は28モデルで支払意思額を出して人の文献値と比べた（3章）。一次採点の「構造モデルは無い」は、需要の側では誤りだった。
- 逐次探索モデル（探索費用の推定）をエージェントの閲覧記録に当てた研究は、検索と arXiv の索引では見つからなかった。ただし、そのまま使える実験環境を持つチームが既にいる（7章）。
- 残る形は「探索モデルは、エージェントに当てはまるのか」を検定する研究である。当てはまれば反実仮想の道具になり、当てはまらなければ「位置効果は探索費用ではない」という知見になる（筆者の見解）。

**いちばんの勝ち筋**: 閲覧（詳細を開く）と選択を分けた模擬サイトで、表示順・価格・閲覧の費用を無作為化する。探索モデルを推定し、使っていない実験条件（順位の付け替え）での実測と予測を突き合わせる。人の側は、同じ推定コードを Expedia の公開データに当てて比べる。

**いちばんの懸念**: Wadi・Ma（McGill）は、閲覧と選択を分けた環境・無作為な表示順・10,500セッション・人の基準データを既に持つ。2か月で5版を出している。次の版で探索モデルを足されると、こちらの新規性は消える。

**勧める条件（人が確かめること）**

1. 「離散選択を当てて人と比べる」部分を成果に数えない。探索モデルと、その検証に絞る。
2. 月1の終わりに、探索モデルの先行が出ていないかをもう一度調べる（9章の撤退条件）。
3. モデルの版で結果が入れ替わることを、弱点でなく研究の対象にする（6章）。

## 2. 問いと、なぜ今か

### 問い

AI 購買エージェントが一覧のページから商品を調べて選ぶとき、その行動は「探索費用を払って情報を得る」というモデルで書けるか。書けるなら、順位付け・広告・価格を変えたときの結果を予測できるか。

### 答えが出ると誰の判断が変わるか

| 誰 | 変わる判断 |
|---|---|
| プラットフォーム | 上位の枠にどれだけの価値が残るか。広告枠の値付け。エージェントに一覧をどう渡すか |
| 売り手 | 順位に払うか、表示する属性（価格・評価・説明文）を磨くか |
| 競争当局・消費者保護 | 自社優遇や「スポンサー」表示の規律を、エージェント経由の購買にどう当てるか |
| 探索モデルを使う研究者 | 人むけに作ったモデルと推定値を、エージェントが混ざる市場の反実仮想に使ってよいか |

### なぜ今か

- 模擬サイトでの監査実験が2025年に出た。位置・スポンサー表示・推薦バッジへの反応は大きく、モデルによって向きまで違う（[Allouah ほか (2025)](https://arxiv.org/abs/2508.02630)）。
- 2026年には、閲覧と選択を分けた実験と、人のフィールドデータとの比較が出た（[Wadi・Ma (2026)](https://arxiv.org/abs/2608.22697)）。
- 理論は2026年に急増した（3章の C）。理論が置く「エージェントの探索費用」「選び方」を、データで確かめた研究は少ない（筆者の見解）。
- 実在のサイトでは、エージェントの出入りをめぐる争いが起きている。Amazon は2025年11月に Perplexity を提訴した（[Bloomberg の報道](https://www.bloomberg.com/news/articles/2025-11-04/amazon-demands-perplexity-stop-ai-agent-from-making-purchases)。検索結果の要約のみ。現在の状況は未確認）。

### 割れている点

- **位置効果は残るのか。** Allouah ほかは「大きく、モデルごとに向きが違う」と言う。Wadi・Ma は「閲覧には効くが人より小さく、選択への効果はモデル次第」と言う。前者は8件を格子状に並べた1画面、後者は100件の一覧である。同じ環境での比較は見つからなかった。
- **位置効果の形。** 人は上ほど有利である（Ursu）。エージェントは U 字だと Wadi・Ma は報告する。探索費用が位置とともに増えるというモデルでは、U 字は説明しにくい（筆者の見解）。
- **人の側でも、位置効果の経路は割れている。** Ursu は探索費用の経路だと言う。Greminger は、それでは購入への効果を過小に出すと言う。
- **係数は選好か。** Kireyev は、ロジットの係数の大きさは選好の強さと決め方の一貫性が混ざると書く。比でしか比べられない。

## 4. 未解決の問い

検索の範囲で、答えが見つからなかった問いである。「空いている」と断定はできない。

1. **逐次探索モデルは、エージェントの閲覧と選択に当てはまるか。** モデルが予測する順序・やめ時・選び方（6章）を、エージェントは守るか。当てはまらないなら、何が代わりの説明か（文脈の中ほどを見落とす性質など）。
2. **エージェントの「探索費用」とは何か。** 一覧は丸ごと文脈に入るので、読む手間は無い。費用に当たるのは、ツール呼び出しの回数・トークンの料金・待ち時間か。費用を実験で動かすと、閲覧はモデルの予測どおりに減るか。
3. **推定したモデルは、使っていない条件を予測できるか。** 順位を効用の順に付け替えたときのシェアを、当てられるか。エージェントでは反実仮想を実際に走らせられるので、直接に確かめられる。
4. **版・推論の強さ・指示文が変わると、どのパラメータが動くか。** 選好か、探索費用か、尺度（一貫性）か。動くのが尺度だけなら、反実仮想の寿命は思うより長い。
5. **人とエージェントが混ざる市場で、順位と広告枠の価値はどう変わるか。** 売り手の価格と表示の反応を入れた均衡。ここは仮定が多く、先に1〜3が要る。

### API の料金の概算の出し方

- 式: セッション数 ×（1セッションの入力トークン×入力単価 ＋ 出力トークン×出力単価）。入力は一覧の長さ×ターン数でほぼ決まる。
- 目安: Wadi・Ma は、1セッションの費用を約 0.011 ドル（軽いモデル）〜0.28 ドル（重いモデル）と報告する（100件の一覧、定価、キャッシュなし）。
- 仮に5モデル×6,000セッションなら 30,000 セッションで、330〜8,400 ドルの幅になる（筆者の概算。**仮定**。各社の価格表は確かめていない）。
- 先に各モデル200セッションの試走でトークン数を測り、見積もりを出してから人が予算を決める。バッチ API や公開重みのモデルで下げられる。

### 商品の実データを模擬サイトに載せる場合

- Allouah ほかは、Amazon のサイトの公開情報から商品を作ったと書く。Kireyev は4つの予約サイトのホテルを使った。どちらも、元サイトの規約との関係は論文の要約からは分からない。
- 実在の商品名・画像・説明文は、収集の仕方（自動取得の禁止）と著作権・商標の両方に当たりうる。再現パッケージで配れないおそれがある。
- 勧める順（筆者の見解）: ①合成の商品（属性を自分で生成する。識別にも有利）、②ライセンスが明示された公開の商品データ、③既存の環境の同梱データ（条件を著者に確かめてから）。②の候補に Amazon の SQID と Wayfair の WANDS がある（Krishnamoorthy・Han が使用）。ライセンスは未確認。
- 実在のブランド名は、LLM の事前知識を呼び込む。選好の推定に混ざるので、架空の名前の条件も必ず作る。

### 実在の EC サイトにエージェントを走らせない理由

- **規約。** Amazon の利用規約は、ロボットなどの自動取得の道具を禁じ、2025年5月には AI エージェントに名乗ることを求める規則を足したと報じられている（[The Fashion Law の記事](https://www.thefashionlaw.com/amazons-ai-shopping-battle-puts-website-terms-to-the-test/)。検索結果の要約のみ。条文は未確認）。訴訟も起きている。
- **第三者への影響。** 実在のサイトでの閲覧・クリック・注文は、売り手の広告費や在庫、順位の学習に影響する。相手の同意が無い介入で、倫理審査の対象になりうる（`ETHICS.md` 第5条。エージェントは人に対して自分から送信しない）。
- **識別。** 実在のサイトでは順位も価格も無作為化できない。この研究に要る変動が得られない。
- したがって、規約の上でも設計の上でも、模擬サイトだけを使う。

## 6. 外生変動の候補（識別の源と、検証の設計に読み替える）

構造推定のテーマなので、「どの変動がどのパラメータを決めるか」「取り置きデータでの確かめ方」「反実仮想に要る仮定」の順に書く。逐次探索モデルの性質の記述は、筆者の整理である。原典（Weitzman、Ursu・Seiler・Honka）の本文では確かめていない。

### どの変動がどのパラメータを決めるか

| パラメータ | 決める変動（すべて実験者が無作為化できる） | 人のデータとの違い | 弱くなる場面 |
|---|---|---|---|
| 選好（価格・評価・レビュー数への重み） | 一覧に出す属性の無作為化。Allouah ほか・Kireyev と同じ | 人では価格が品質と相関し、操作変数が要る。ここでは要らない | 係数の水準は尺度（決め方の一貫性）と混ざる。比だけが比べられる（Kireyev） |
| 位置効果 | 表示順のセッションごとの無作為化。Ursu の実験、Wadi・Ma と同じ | 同じ | 位置が「閲覧の費用」に効くのか「見落とし」なのかは、これだけでは分からない |
| 探索費用 | **閲覧の費用を直接に動かす。** ツール呼び出しの上限、1回ごとの料金の告知、待ち時間。Wadi・Ma (2026b) の発想に近い | 人では費用を動かせず、位置や関数形に頼る。ここがいちばんの利点 | 告知した料金を、エージェントが費用として扱うとは限らない。扱わないこと自体が結果になる |
| 詳細ページで分かる情報の分布（事前の信念） | 詳細ページに出す情報を実験者が生成する。分布が既知 | 人では合理的期待を仮定する。ここでは真の分布が分かる | エージェントが分布を知らない。学習データ由来の思い込みが入る |
| 外部オプション | 「何も選ばず終える」道具を残す。指示文で予算や必要度を動かす | 同じ | 指示文に従って必ず買うモデルでは、識別できない |
| モデル間・版の間の異質性 | モデル×版×推論の強さ×指示文を、要因として割り付ける | 人の観察されない異質性に当たる | 同じ条件の反復は独立でない。温度0では変動が無い |

### モデルが予測すること（検定できる形）

逐次探索モデルは、パラメータを推定しなくても検定できる予測を持つ。

| 予測 | 確かめ方 | 破れていたら |
|---|---|---|
| 閲覧の順序は、一覧の情報から計算できる指標の高い順になる | 閲覧の順序の記録 | 順序が位置だけで決まるなら、探索ではなく走査である |
| 閲覧をやめるのは、手元の最良が、残りの指標を上回ったとき | やめた時点の記録 | 決まった件数でやめるなら、費用と便益の比較ではない |
| 選ぶのは、閲覧した中で最良のもの | 選択と閲覧の突き合わせ | 閲覧していない商品を選ぶ、最良でないものを選ぶ |
| 閲覧の費用を上げると、閲覧数は単調に減る | 費用の条件の間の比較 | 反応しないなら「探索費用」という解釈は成り立たない |
| 位置は閲覧に効くが、閲覧した後の選択には効かない（人では Ursu の結果） | 閲覧を条件にした選択 | 選択に直接効くなら、位置は効用か注意の偏りに入っている |
| 位置の不利は、下ほど大きい（単調） | 位置ごとの閲覧率 | U 字なら、位置ごとの探索費用では書けない。Wadi・Ma は U 字を報告済み |

### 取り置きデータでの当てはまりの確かめ方

- 推定に使うのは、表示順と属性を無作為化した条件だけにする。
- 取り置く条件: ①閲覧の費用を変えた条件、②効用の順・価格の順・スポンサー枠つきなど、順位の規則を変えた条件、③一覧の長さを変えた条件、④推定に使わなかった商品分類。
- 取り置いた条件でのシェア・閲覧数・やめ時を、推定したモデルで予測し、実測と比べる。比べる相手は、探索を入れない条件つきロジット（Allouah ほかの型）と、位置のダミーだけの記述モデルである。
- 成功基準と棄却条件の数値は、ここでは決めない。段階3〜4で人が決める。例（**仮定**）: 取り置いた順位の規則でのシェアの予測誤差が、探索なしのロジットより小さいこと。
- 利点: 人のデータでは、反実仮想は走らせられない。エージェントでは走らせられる。モデルの検証が、ふつうの構造推定より強くできる。

### 反実仮想に要る追加の仮定と、それぞれの弱点

| 仮定 | 何に要るか | 弱点 |
|---|---|---|
| 売り手の反応（価格・説明文・広告入札） | 均衡の反実仮想 | 模擬サイトには売り手がいない。売り手のモデルを外から置くことになり、結論は置き方に依る。売り手も LLM にする手はある（Huang・Xiao、Magentic）。その場合は「売り手のモデルの版」にも依る |
| 版が変わっても選好と探索の規則が保たれる | 推定値を将来に当てる | **保たれないと分かっている。** GPT-4.1 と GPT-5.1 で位置の係数の向きが逆（Allouah ほか）。一次採点の E（2点）のとおり |
| 指示文と足場（ツールの形、推論の強さ）が保たれる | 実際に使われるエージェントに当てる | 推論の強さで位置効果が変わる（Wadi・Ma）。依頼人をプラットフォームにするとスポンサーの扱いが変わる（Wadi・Ma 2026c） |
| 人とエージェントの比率、人の側のパラメータ | 混ざった市場の反実仮想 | 人の値は2012〜2013年のホテル検索のもの。別の分類・現在に当てるのは仮定である |
| プラットフォームの目的関数 | 最適な順位・広告枠 | 収益・取引数・厚生のどれかで答えが変わる。人では対立は小さいと Greminger は報告する。エージェントでは未知 |
| 厚生の物差し | 「消費者が得をしたか」 | 推定されるのはエージェントの見かけの効用で、依頼人の効用ではない。厚生は、依頼人の選好（指示文で与えた真の選好）に照らして測るべきである（筆者の見解） |

### 根本の批判：LLM に効用や探索費用という解釈を与えてよいか

- **尺度の問題。** ロジットの係数は、選好の強さと決め方の一貫性の積である。Kireyev は、価格と品質の係数がモデル間で一緒に動く（相関 0.55）こと、比を取ると一貫性と無相関になる（−0.09）ことを示す。探索モデルでは、探索費用も効用の単位で測られる。金額に直した値だけを報告する。
- **費用が無い。** 一覧は丸ごと文脈に入る。「下の方を読む手間」は無い。位置効果は、注意の配り方の癖（文脈の中ほどの見落とし）かもしれない。その場合、モデルが出す「探索費用」は別物の名前を借りているだけになる。上の検定表は、この区別のためにある。
- **安定した対象が無い。** 版・推論の強さ・指示文で行動が変わる。推定値は「ある版の、ある設定の方針」の記述である。人の母集団のパラメータとは意味が違う。
- **人の代わりではない。** [Gui・Toubia (2023)](https://arxiv.org/abs/2312.15524) は、LLM に人を演じさせた実験では、条件の変更が他の変数まで動かすと論じる（検索結果の要約のみ）。T105 は LLM を人の代わりにせず、エージェントの方針そのものを対象にする。Kireyev と同じ立場である。
- **反実仮想は走らせればよい、という批判。** 買い手だけの反実仮想は、実験で直接に得られる。構造モデルが要るのは、①組合せが多すぎて走らせきれない設計の探索、②売り手が動く均衡、③人の文献との比較の共通の物差し、の3つに限られる（筆者の見解）。ここを本文で正面から書かないと、査読で止まる。
- **筆者の立場（見解）。** 構造モデルを「真の姿」としてではなく、反証できる圧縮として扱う。当てはまりが悪ければ、それを結果として出す。

### この設計の弱点

- 環境を自作すると、結果は環境の作り（ツールの形、1頁の件数、指示文）に依る。Allouah ほか・Wadi・Ma の設定を再現する条件を入れ、先行の数値を再現してから進める。
- 設定を選ぶ自由度が大きい。モデル・版・指示文・取り置く条件を、ロックで固定する。
- 同じモデルの反復は、独立な消費者ではない。標準誤差の単位（セッションか、課題か、モデルか）をロック前に決める。「母集団」をモデルの集合と見るなら、5〜10個しかない。
- 提供元がモデルを差し替えると、同じ名前で結果が変わる。実行日と版の識別子を全件残す。公開重みのモデルを必ず含め、再現できる核を作る。

## 8. AI が効く所・効かない所

| 工程 | 律速 | AI の効き方 |
|---|---|---|
| 文献の追跡 | 情報処理 | よく効く。月に数本出るので、追い続ける必要がある |
| 模擬サイトとエージェントの足場の実装 | 情報処理 | よく効く。ACES と Magentic のコードが参考になる |
| 選択記録の生成 | 計算・料金 | よく効く。律速は予算と、提供元の速度制限 |
| 探索モデルの推定コード | 情報処理 | 効く。Greminger の公開コードがある。尤度の実装の誤りは、合成データで回収を確かめて防ぐ（段階6） |
| 合成データでの回収の点検 | 計算 | よく効く |
| 「何を探索費用とみなすか」の設計 | 概念の整理 | 効きにくい。ここで論文の価値が決まる |
| 売り手の反応とプラットフォームの目的の置き方 | 産業組織の判断 | 効きにくい。人が決める |
| Expedia データと商品データの規約の確認 | 利用許可 | 効かない。人が規則を読み、必要なら問い合わせる |
| 有力チームに対する位置づけと、出す速さの判断 | 判断 | 効かない |

- データの利用許可は、主な律速ではない。エージェントの側は自分で作れる。
- 律速は、速さ（競合より先に出す）と、解釈の設計（6章の根本の批判に耐える形）である。
- 調べる側の AI が、調べられる対象でもある。自社のモデルの結果を AI が書くときは、人が数値を実行結果と突き合わせる（`ETHICS.md` 第6条・第8条）。

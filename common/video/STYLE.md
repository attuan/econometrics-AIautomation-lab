# 動画の規約（全プロジェクト共通）

対象は、経済学の学部生から、新しく来た研究者まで。
1本の動画で、1つの文書（ラボの進め方、または1つの研究仮説）を「何が問題で・何を確かめ・どう確かめ・何が分かれば面白いか」まで直感で分かるようにする。
動画はブラウザで動く SVG のアニメーションである。ビルドは要らない。`index.html` を開けば再生できる。

- 1本 = `videos/<ID>.js` 1ファイル。`index.html` が読み込んだ順に連続再生する。
- 読み上げ（ブラウザの音声合成）をオンにすると、字幕がそのまま音声になる。字幕は耳で聞いて分かる話し言葉で書く。
- 内容の正本は文書の側にある（ラボ案内は `README.md`、研究提案は `<project>/paper/main.tex`）。動画だけにある事実を作らない。

## ファイルの形

```js
VIDEO({
  id: 'V01', title: '仮説の短い名前', subtitle: '問いを一文で',
  hook: 'タイトルカードで流す一言',
  scenes: [
    scene('サイドバー用の短い名前', '主張の形の見出し', [
      '字幕の1文め。',                                   // 1文40字以内。時刻は自動で割り振られる
      '字幕の2文め。',
    ], (g, T) => {                                       // g = SVG の <g>（1600×900）。T[i] = i 番目の字幕の時刻
      const ax = axes(g, 300, 220, 700, 440, [0, 10], [0, 10]);
      const line = fitline(g, ax, 0, 2, 10, 6, C.blue);
      return t => {                                      // t = シーン内の秒。毎フレーム呼ばれる
        drawLine(line, prog(t, T[1], 1.2));              // 2文めに合わせて、1.2秒かけて線を描く
      };
    }),
  ],
});
```

- `scene()` を使わずに `{ title, dur, subs: [[秒, 文], ...], setup(g) { ...; return t => {...}; } }` を直接書いてもよい。
- **`t => {...}` は t だけで絵が決まるように書く。** シーク・巻き戻しで同じ絵になる。乱数は `setup` の中で `rng(種)` を使う。
- タイトルカードはプレイヤーが先頭に自動で入れる。自分で作らない。上段の文言は `index.html` の `<body data-series="...">`。
- `id:`・`title:`・`subtitle:` は `VIDEO({` の直後の1行に書く（ポータルが一覧を作るときに読む）。
- 部品は `lib.js` にある。足りない図形は自分の動画ファイルの中で関数にする。`lib.js`・`player.js`・`style.css` は編集しない。

| 種類 | 部品 |
|---|---|
| 基本 | `el` `set` `grp` `txt` `img` `box` `heading` |
| 時間 | `prog` `show` `dim` `lerp` `clamp` `rng` `timeline` `scene` |
| 線・グラフ | `arrow` `drawLine` `axes` `scatter` `fitline` `coef` |
| 絵 | `paper`（論文）`table`（データ表）`computer`（AI・計算）`person`（人）`gate`（関門）`lock`/`setLock`（ロック）`pkg`（ライブラリ）`lens`（監査）`tick`（確認済み） |

- 画像は `<project>/paper/figs/` の自作図だけを `img()` で使ってよい。外部 URL は読まない。基本は SVG で描く。
- URL: `#<ID>` でその動画を開く。`?t=<秒>` で開始位置、`?scene=<番号>` で頭出し、`?bare=1` で画面だけ（埋め込み用）。

## 認知負荷を下げる規約

- **1シーン1メッセージ。** 見出しは主張の形にする（「見てから選ぶと、偶然を拾う」）。
- 同時に画面に出す文字ラベルは **5個まで**。文章は字幕に、画面は図に。全体図（8段階など）は例外とするが、話していない所は `dim()` で薄くする。
- 要素は **出てくる順＝話す順**。字幕の時刻 `T[i]` に合わせて `show()` する。最初から全部出さない。
- 新しい用語は、初めて出る所で「用語 = 一言の意味」の札を出す（例:「平行トレンド = 処置がなければ、差は同じまま」）。
- たとえを先に、本物の式や図を後に。式は1シーンに1本まで。
- 字幕は1文40字以内。表示時間は「文字数÷7」秒以上。シーンの `dur` は最後の字幕＋3秒以上（`scene()` を使えば自動で守られる）。
- 字幕では括弧書き・記号・略語の連発を避ける。略語は言い換える（「差の差、つまり前後の変化を二つの群で比べる方法」）。
- 動きは意味のあるものだけ（線が伸びる、点が移る、区間が狭まる）。0.5〜1.5秒でゆっくり。

## 数値の扱い

- 数値は正本に書いてあるものだけ使う。正本にない数値を作らない。
- **予想値を実測のように言わない。** 予想・仮定・合成データの結果は、画面に「予想（筆者の仮定）」「合成データ」と出し、字幕でもそう言う。
- 架空の模式図には、画面に「例（架空の模式図）」と書く。
- 推定値を出すときは、信頼区間を `coef()` で一緒に出す。点だけを出さない。
- 確証（ロックした仕様）と探索（データを見た後の分析）を、色と言葉の両方で区別する。

## 色の意味（全動画共通）

| 色 | 意味 |
|---|---|
| `C.blue` | 処置群・主役・強調 |
| `C.gray` | 対照群・比較の相手 |
| `C.green` | 確証・支持・成功 |
| `C.yellow` | 探索・まだ確かめていないこと |
| `C.red` | 問題点・棄却・やってはいけないこと |
| `C.purple` | AI・計算・シミュレーション |
| `C.orange` | 人の判断（関門）・ロック |
| `C.cyan` | データ・文献 |
| `C.mute` | 補助・軸・注釈 |

意味を色だけで伝えない。形・位置・ラベルでも区別する（処置群は実線で上、対照群は灰色で下、など）。

## レイアウト

- 背景は `C.bg`。見出しは `heading()`（`scene()` が入れる）で左上に固定する。
- **y > 780 は字幕の領域。** 図も文字も置かない。
- 文字の大きさ: 見出し 44 / ラベル 28〜40 / 注釈 22 以上。22 未満の文字を作らない。
- 左右2分割（前と後、たとえと本物、支持と棄却）を多用してよい。

## 構成の型①：研究提案ビデオ（1仮説 = 1本、6〜9分、9〜12シーン）

内容の正本は `<project>/paper/main.tex`。3つのトラックで、同じ型を読み替える。

| # | シーン | 因果推論 | 構造推定 | 推定量・計量手法 |
|---|---|---|---|---|
| 1 | ひと目でつかむ | 何の変動で、誰の、何の効果を測るか | 何のモデルで、どのパラメータを知りたいか | どの推定量の、何を良くするか |
| 2 | なぜ大事か | 答えが出ると、誰の判断が変わるか | 推定できると、どんな仮想の政策を試せるか | 誰が、どの場面で困っているか |
| 3 | 今の知見と限界 | 先行研究の推定値の範囲と、割れている点 | 既存モデルが説明できない事実 | 既存の推定量が外す設定 |
| 4 | 仕組み① | 制度と、使う外生変動を1歩ずつ | 経済主体の選択を1歩ずつ | 推定量の考え方をたとえで |
| 5 | 仕組み② | 推定式と、識別の仮定 | 何のデータの動きが、どのパラメータを決めるか | 式の意味と、成り立つ条件 |
| 6 | 研究仮説 | H1〜を1枚ずつ。何がいくつなら支持・棄却か | 同左（当てはまりの基準も） | 同左（既存手法との差の基準） |
| 7 | 手順 | データ→標本→推定→反証テスト | データ→モーメント→推定→当てはまりの確認 | 設計→合成データ→比較→実データで例示 |
| 8 | 何を見れば白黒がつくか | 支持の場合と棄却の場合の図を並べる（予想と明記） | 同左 | 同左 |
| 9 | 落とし穴と別の説明 | 識別の仮定が破れる筋と、その点検 | モデルの誤りと、感度の確認 | 都合のよい設定だけ試していないか |
| 10 | 面白さ | どちらの結果でも何が分かるか | 同左 | 同左。ライブラリとして誰が使えるか |
| 11 | 判断と次の一手 | Go/No-Go の基準、期間、最初の一歩 | 同左 | 同左 |
| 12 | まとめ | 要点3行 | 同左 | 同左 |

- シーン6では、ロックの状態（未ロック／ロック済み）を画面に出す。
- 結果が出た後に作り直すときは、シーン8を実際の結果に差し替え、確証と探索を分けて見せる。予想の図は消さずに並べる。

## 構成の型②：テーマのディープダイブ（1テーマ = 1本、3〜5分、6〜8シーン）

1. ひと目でつかむ（問いを一文で）　2. なぜ今か　3. 文献の地図（何が分かり、何が割れているか）
4. 使えるデータ（入手の手順と期間、秘匿区分）　5. 外生変動や手法の候補　6. 競合
7. 最初の6か月と撤退条件　8. 判断の材料（勧める・勧めないと、その理由）

人が5分で「着手するか」を決められることが目標である。判断そのものは動画に書かない（人が `decision` 箱に書く）。

## 点検

```sh
tools/check_video.sh <project>/video                 # 構文、全シーンの実行、字幕の規約
tools/check_video.sh --shots <出力先> <project>/video  # 各字幕の時点の絵を SVG で書き出す
```

- 点検が通っても、見た目（重なり・はみ出し・読みやすさ）は分からない。ブラウザで全シーンを一度通して見る。
- ブラウザを使えない環境では、`--shots` の SVG を画像にして見る。

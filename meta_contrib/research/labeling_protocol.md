# 正解づけの手順書（H23）

> 状態: **案**（2026-11-24）。正解づけを始める前に人が確かめて固定する。始めた後に定義を変えたら、変えた日と理由を末尾の更新履歴に書く。
> 目的: 決定モデル（gpt-6-luna）の判定が、人の判定と一致するかを確かめる（H23）。一度だけ行う。合格した判定は、残りの数千本をモデルだけで判定する。

## 3行で言うと

1. **80本の題目と要旨を読み、1本あたり6〜9個の判断をする。** 所要時間は約2時間半。20本ずつ4回に分けてよい。ブラウザの画面で、左に要旨、右のボタンで答える。
2. **雑誌名・著者・年は見ない。決定モデルの答えも見ない。** 表には題目と要旨だけが出る。
3. **迷ったら「?」を付けてメモを書く。** 無理に決めない。

## 1. 何に正解を付けるか（必要な問いの選び方）

検証する仮説（H01, H02, H03, H07, H11, H16, H18, H22, H23, H25）が使う判定のうち、**人の判断が要り、かつ仮説の判定に直接効くもの**だけに正解を付ける。

| 付ける | 判断 | 使う仮説 | 理由 |
|---|---|---|---|
| ○ | T 論文の種類（手法／応用／理論／その他） | H07・H11 の部分標本 | 部分標本の取り違えは全体に効く |
| ○ | C1 誤りを正す | H01, H18 | 仮説の中心。判断が要る |
| ○ | X 小幅な拡張 | H02, H18 | 仮説の中心。判断が割れやすい |
| ○ | C2 道具を作る | H03, H18 | 仮説の中心。判断が要る |
| ○ | G 特定の国・地域・業種が対象 | H07 | 「名前が出る」と「対象である」の区別に判断が要る |
| ○ | B 流行の題材を前面に出す | H16 | 「前面に」の判断が要る |
| ○（手法論文のみ） | S1 理論の保証、S2 実データでの応用、S3 シミュレーション | H11 | 「シミュレーションだけ」はこの3つの組合せで決まる |
| × | 「一流誌らしい文体」（TS） | H25 | H25 は決定モデルが思う「一流誌らしさ」の中身を分解する仮説で、人の正解は要らない |
| × | 具体的な文体の24問（ST01〜ST24） | H18, H25 | 長さ（ST20・ST21）や決まり文句（ST02）などはプログラムで数えて照合する。それ以外は H25 の説明変数で、人の正解が無くても H25 は検定できる |
| × | 要旨の言い換えで内容が保たれたか | H22 | 言い換えを作った後に、別の短い作業（20組）で行う。この手順書の対象外 |

**決め方の原則**: 質問ごと（4問ずつある細かい質問）ではなく、仮説が使う**型**ごとに1つ付ける。仮説の判定は型の単位（その型の質問の平均）で行うので、照合も型の単位で足りる。

## 2. 何本に付けるか

| 標本 | 本数 | 選び方 |
|---|---|---|
| 無作為 | 60本 | 探索用の標本から、雑誌ごとにほぼ同数を無作為に選ぶ |
| 濃い目 | 20本 | 探索用の標本から、下の語を要旨に含む論文を無作為に選ぶ（無作為の60本とは重ねない） |
| **計** | **80本** | 表の中では順番を混ぜる。どちらの標本かは表に出さない |

**80本にした理由**: 「誤りを正す」「流行の題材」は全体の1割前後しかないかもしれない。無作為の60本だけだと「はい」が6本程度しかなく、一致度が測れない。そこで、該当しそうな論文を語で20本足す。語で選ぶのは決定モデルの答えと無関係なので、照合をゆがめない。一致度は、無作為の60本だけの値と80本全体の値の両方を出す。

**濃い目の20本を選ぶ語**（結果を見る前に固定する。大文字小文字は区別しない）:
- 誤りを正す: `misleading`, `biased`, `invalid`, `incorrect`, `commonly used`, `widely used`, `standard practice`, `fails to`
- 流行の題材: `cryptocurrenc`, `bitcoin`, `blockchain`, `covid`, `pandemic`, `esg`, `machine learning`, `artificial intelligence`, `big data`
- 各10本ずつ選ぶ。

**2人目（任意）**: 上司などに、80本のうち無作為の20本だけ付けてもらうと、人どうしの一致度（κ）も出せる。付けなくても H23 の主な判定はできる。

## 3. 進め方

1. `python3 code/04_label_tool.py` で正解づけの画面（`data/derived/label_tool.html`）を作り、`open data/derived/label_tool.html` でブラウザで開く。左に題目と要旨、右に問いとボタンが出る。
   - この画面は手元でだけ開く。要旨を再配布しないため、git にも公開ポータルにも載せない。
   - キー操作: `1`＝はい、`0`＝いいえ、`/`＝?（上から順に未回答の問いへ入る）。`M` `A` `T` `O` で種類。`→` `←` で前後の論文へ。
2. 1本ずつ、題目と要旨を読んで答えを入れる。目安は1本2分。手法論文（M）を選ぶと、証拠の種類の3問が出る。
3. **知っている論文**（著者や雑誌を思い出せる）は「知っている」を押す。分析で外した版も出す。
4. 答えはブラウザに自動で保存される。途中でやめてよい。下の番号の一覧で、回答済みの論文は色が変わる。
5. 終わったら（途中でも）「CSV を書き出す」を押す。`label_sheet_<名前>_<日付>.csv` が保存されるので、`data/derived/` に置く。あとは AI が集計する。別のブラウザで続けるときは「CSV を読み込む」で戻せる。

**やらないこと**: 決定モデルの答え（`predicates.csv`）を、正解づけが終わる前に開かない。論文を検索して雑誌や本文を調べない。題目と要旨だけで判断する。

## 4. 答え方

各列に `1`（はい）、`0`（いいえ）、`?`（判断できない）のどれかを書く。T だけは `M`（手法）・`A`（応用）・`T`（理論）・`O`（その他）のどれか。S1〜S3 は T が `M` のときだけ付け、それ以外は空欄にする。

### T 論文の種類

| 値 | 定義 | 例 |
|---|---|---|
| M 手法 | 主な貢献が、推定量・検定・推論の手続き・計算法など、統計・計量の方法そのもの | 新しい推定量を提案し性質を示す。既存の検定の性能を比べる |
| A 応用 | 主な貢献が、データから得た経済についての知見 | ある政策の効果を推定する。ある国の物価と為替の関係を調べる |
| T 理論 | 主な貢献が、経済主体や市場の理論モデル。新しい統計手法も実証の知見も無い | 均衡の存在を示す。メカニズム・デザイン |
| O その他 | 上のどれでもない | サーベイ、データの紹介、ソフトウェアの紹介 |

- 手法を提案して実データに当てている論文は、**主な貢献**で決める。要旨の大半が手法の性質の話なら M、得られた経済の知見の話なら A。
- 迷ったら、要旨の最初の2文が何を約束しているかで決める。

### C1 誤りを正す

**定義**: 多くの研究者が使っている手法・慣行・仮定が、誤った結論を生みうることを示している。直し方を出しているかは問わない。

| 例 | 答え |
|---|---|
| 「よく使われる○○推定量は、△△のとき大きく偏る。その理由を示し、代わりの推定量を出す」 | 1 |
| 「既存研究の多くが用いる□□の仮定は、データでは成り立たない」 | 1 |
| 「新しい推定量を提案する。既存の推定量より効率がよい」（既存の手法が誤るとは言っていない） | 0 |
| 「ある国の先行研究と違う結果を得た」（手法や慣行の誤りではなく、結果の違い） | 0 |

- 「効率が悪い」「計算が遅い」だけでは 0。**結論を誤らせる**（偏り、誤った有意、誤った解釈）と言っているときに 1。

### X 小幅な拡張

**定義**: 既に確立した分析や手法を、ほぼそのまま新しい国・地域・業種・期間・データに当てているか、既存の手法の仮定を1つ緩める・変数を1つ足すなどの小さな変更にとどまる。

| 例 | 答え |
|---|---|
| 「ARDL モデルで、△△国の輸出と成長の関係を調べる」 | 1 |
| 「既存の□□検定を、構造変化を1つ許す形に拡張する」 | 1 |
| 「既存の手法が誤る理由を示し、新しい枠組みを出す」 | 0 |
| 「新しい行政データを接続して、これまで測れなかった量を測る」（データが新しいだけでなく、問いが新しい） | 0 |

- **データだけが新しく、問いと方法が既存研究と同じなら 1**。
- 判断に迷う典型: 新しい国に当てつつ、手法も少し変えている → 変更が「1つの仮定・1つの変数」程度なら 1。

### C2 道具を作る

**定義**: 多くの研究者が、さまざまな場面で使える汎用の推定量・検定・手続き・ソフトウェアを提供している。

| 例 | 答え |
|---|---|
| 「パネルデータ一般に使える、頑健な標準誤差の計算法を出す。R パッケージを公開する」 | 1 |
| 「操作変数が弱いときにも使える検定を出す」（多くの応用で使える） | 1 |
| 「ある特定の市場モデルの推定法を出す」（そのモデルを使う人に限られる） | 0 |
| 応用論文（T が A） | 原則 0 |

- 「どれくらいの人が使えるか」で決める。特定の1つのモデル・1つのデータ専用なら 0。

### G 特定の国・地域・業種が対象

**定義**: 分析の対象として、特定の国・地域・都市・業種を名指ししている。

| 例 | 答え |
|---|---|
| 「日本の家計のデータを用いて…」 | 1 |
| 「観光業の需要を予測する」 | 1 |
| 「手法を米国の賃金データに当てて示す」（手法論文の例示） | 1 |
| 「OECD 諸国のパネル」 | 1（地域を名指ししている） |
| 「国のパネルデータ」（どの国か書いていない） | 0 |

- 手法論文の例示でも、国や業種を名指ししていれば 1。H07 は応用論文に絞って検定するので、ここで区別しなくてよい。

### B 流行の題材を前面に出す

**定義**: 題目または要旨の1文目で、流行の題材（暗号資産・ブロックチェーン・COVID-19・ESG・気候金融・ビッグデータ・AI や機械学習の宣伝的な使い方）を前面に出している。

| 例 | 答え |
|---|---|
| 題目が「COVID-19 期の株価の変動」 | 1 |
| 1文目が「機械学習は経済予測を一変させた」 | 1 |
| 「高次元の推定に Lasso を用い、その推定量の性質を示す」（機械学習の手法を研究対象として扱う） | 0 |
| 要旨の終わりに「COVID-19 期を含む」と一言ある | 0 |

### S1〜S3 証拠の種類（T が M のときだけ）

| 列 | 定義 |
|---|---|
| S1 理論の保証 | 一致性・漸近正規性・妥当性・最適性など、手法の性質についての理論的な結果を述べている |
| S2 実データでの応用 | 実データに当てて手法を示している |
| S3 シミュレーション | モンテカルロ実験・シミュレーションで性能を評価している |

- 要旨に書かれていなければ 0。本文にありそうでも、要旨に無ければ 0。

## 5. 集計（AI が行う）

- 決定モデルの答えは、型ごとに質問の P(はい) の平均を取り、0.5 以上を「はい」とする。T は P1・P2・P3 のうち最も高いもの（どれも 0.5 未満なら O）。
- 人の `?` は集計から外し、件数を報告する。
- 型ごとに、正解率、AUC（P の平均と人の答え）、コーエンの κ を出す。無作為の60本だけと、80本全体の両方を出す。
- **「はい」が8本未満の型は、一致度を「判定できない」とし、正解を足すか、その型の仮説の結論を弱めて書く。**
- 2人目がいれば、20本について人どうしの κ も出す。
- 合格の基準は H23 の成功基準による（ロック前に人が決める）。不合格の型は、質問文を直して、その型だけ照合し直す。

## 6. この手順書が測れないこと

- 人の判断そのものが正しいかは測れない。2人目の κ で、人どうしの揺れの大きさだけは分かる。
- 題目と要旨だけで判断するので、本文を読めば違う答えになる論文もある。この研究の判定はすべて題目と要旨だけに基づくので、照合も同じ条件で行う。
